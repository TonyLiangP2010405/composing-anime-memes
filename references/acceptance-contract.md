# 完整 GIF 验收合同

## 证据顺序

1. 单个样板的配置与真实蒙版验证通过。
2. 真实后端生成该样板 GIF。
3. 机械验证通过。
4. 模型完整播放该样板并初审。
5. 用户确认视觉方向后才扩展；正式交付前完成用户终审并绑定散列。

前一级通过不能代替后一级。单样板未通过时不得继续批量制作。后续模板复用未变化的配置和资产时，不重复运行相同机械检查；新增或改变的形状、蒙版、轨迹和输出必须分别验证。最终视觉验收不能因此被省略。

## 机械验证

至少检查：

- 输入头像数量、无文字约束、尺寸、比例、帧时长和循环。
- GIF 至少两个不同帧，真实后端可重复出图。
- 每张头像独立影响目标区域，不影响其他 actor。
- 允许变化蒙版外原片像素保持一致。
- 透明、非方形和极端比例头像不报错。

`MECHANICAL_ONLY` 不得改写为“效果合格”。

## 模型初审

每个模板都按正常速度播放完整 GIF，不只查看开头、中段和结尾静帧：

- 头像身份和动作关系是否清楚。
- 是否仍有非照片矩形贴片。
- 手、头发、杯口、牙齿等前后关系是否正确。
- 是否漂移、跳变、闪烁或突然缩放。
- 循环接缝是否自然。
- 实际聊天显示尺寸下是否可辨认。

抽样可以用于调参和选择下一轮场景，不能替代全量初审。

## 用户终审与散列绑定

模型初审后向用户提供可播放 GIF、三帧图和初审记录。用户确认后，在场景配置写入：

```json
{
  "visual_approval": {
    "reviewer": "user",
    "approved": true,
    "sha256": "实际输出 GIF 的 64 位散列",
    "source_sha256": "原始素材的 64 位散列"
  }
}
```

审批只对该精确 GIF 有效。重新渲染、改变头像、蒙版、轨迹、帧时长或源素材后，`approved` 必须重置为 `false`，重新执行初审和终审。

## 交付格式

数量只能来自实际验收记录；没有记录时写“未核验”，不得用 0、估算值或计划数代替。

```text
机械验证：通过 X/Y，命令与结果（无记录时写未核验）
完整 GIF 模型初审：通过 X/Y，证据路径（无记录时写未核验）
用户终审：通过 X/Y（无记录时写未核验）
待修或 reject：键名、原因、下一步
```

存在未验收项时只能报告“部分完成”。不得把通过数量、可渲染数量或测试数量改写为“全部契合”。
