# 构图模式与必要资产

## 快速选择

| 问题 | 选择 |
|---|---|
| 头像是否代替玩偶、抱枕或动作中的角色？ | `character` |
| 头像是否就是杯身、衣物或包装上的印刷图案？ | `print` |
| 画面是否本来就在展示照片、书页或相框？ | `photo` |
| 目标是否为黑板粉笔画？ | `chalk` |
| 是否无法说清头像与动作的关系，或目标一直看不清？ | `reject` |

## `character`：头像参与动作

必要资产：

- 每个 actor 的头像索引和角色身份。
- 非矩形头部或角色轮廓；不能使用矩形照片排版。
- 原角色需要保留的耳朵、头发、蝴蝶结、身体、牙齿、手臂等前景。
- 逐帧目标区域、轨迹和允许变化蒙版。
- 多人各自独立的区域；同一输入变化不得改写另一角色。

完整配置见 `examples/character_scene.json`。关键字段：

- `mode`、`reference_index`、`image_count`。
- `actors[].image`：输入头像索引。
- `actors[].change_mask`：参考帧允许变化区域。
- `actors[].frames[].index/quad/mask`：逐帧位置与遮挡。

张口、进入画面等动作应使用场景参考帧，不是机械取 GIF 中点。跟踪不稳定时使用人工关键帧插值或缩短片段；仍不稳定则 `reject`。

## `print`：头像成为物体印花

- 去除无意义照片白底和矩形硬边。
- 保留原物体曲面、褶皱、纹理、高光和环境色。
- 印花颜色与对比度必须足以辨认，不能用低透明度把头像洗没。
- 手、杯口、头发和缝线保持在上层。

## `photo`：头像本来就是照片

- 允许矩形，但要有真实纸边和纸张底色。
- 照片随页面透视、弯曲和环境光变化。
- 手指和头发必须在照片上方。
- 多人照片可以分别排版，不得互相串色。

## `chalk`：头像变成线条

- 使用亮度与边缘提取可辨认轮廓。
- 白色背景不得生成矩形底板。
- 保留黑板颗粒、板擦痕迹和原角色前景。
- 清除边缘检测产生的人工图像外框。

## `reject`：不适合制作

出现以下任一情况时，淘汰、换素材或明确留为待修：

- 头像最终尺寸小到无法辨认。
- 无法解释头像和场景动作的关系。
- 跟踪漂移、频繁穿帮或遮挡无法可靠标注。
- 必须强行拉伸、放大或降低清晰度才能掩盖问题。

`reject` 必须写 `reason`，不得带正式视觉审批。
